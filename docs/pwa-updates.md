# Tiny Week PWA 업데이트

## 동작

앱 실행, 화면 복귀(`pageshow`, `visibilitychange`), 인터넷 재연결 때 서비스 워커 업데이트를 확인한다. 화면이 계속 열려 있으면 60초마다 확인하며, 백그라운드나 오프라인에서는 요청하지 않는다. 중복 확인은 하나로 합친다.

새 서비스 워커는 필수 파일을 모두 받은 뒤에만 활성화된다. HTTP 캐시를 우회하고, 설치 중 버전 파일이 바뀌면 해당 설치를 거부한다. 파일 누락이나 네트워크 실패 시 현재 버전을 유지하며 다음 실행·복귀·온라인 전환·주기 확인에서 재시도한다.

활성화된 워커의 버전과 현재 화면의 버전이 다르면 화면을 한 번 다시 불러온다. 다음 상황에서는 적용을 미룬다.

- 영화 또는 식단 선택 창이 열린 상태
- 입력칸이나 메모칸에 포커스가 있는 상태
- 한글 등 문자 조합 입력이 진행 중인 상태
- 앱이 백그라운드인 상태

저장·편집 종료 또는 화면 복귀 후 자동으로 적용한다. 명시적으로 편집 창을 닫는 동작은 기존과 같이 저장하지 않은 편집을 취소한다. 업데이트 자체는 로컬 식단·영화·메모 기록을 삭제하지 않으며, 자동 적용 후에도 보던 주와 회전 설정을 유지한다. 같은 이전 버전→새 버전 전환에서 갱신을 반복하지 않도록 세션 단위 보호 장치를 둔다.

## 배포 규칙

1. 코드나 정적 파일을 바꾸는 배포마다 `app-version.js`의 `TINY_WEEK_VERSION`을 새로운 값으로 올린다. 화면과 서비스 워커가 이 한 파일을 공유한다.
2. `index.html`, `app.js`, `app-updates.js`, `app-version.js`, `service-worker.js`와 관련 정적 파일을 함께 배포한다. 서비스 워커의 필수 파일 목록에 새 파일을 넣으면 실제 배포에도 반드시 포함한다.
3. 기존 버전이 설치된 상태에서 새 버전으로 자동 적용되는지 확인한다. 새로 설치한 앱의 첫 화면만 확인하는 것은 업데이트 검증을 대신하지 않는다.

자동 업데이트 코드가 없는 v12 이하 화면은 새 코드를 실행할 수 없다. 첫 전환에서는 새 워커가 설치된 뒤 한 번 새 페이지를 불러와야 한다. 그 이후 v13부터는 위 확인·적용 처리가 작동한다. iOS 홈 화면 앱의 정지·복귀와 실제 키보드 조합 입력은 아이폰에서 별도로 확인해야 한다.

## 다른 앱에 적용할 때

`app-updates.js`의 확인·적용 흐름을 참고하되 서비스 워커 URL과 저장 키를 해당 앱의 이름으로 바꾼다. `canReload`에는 그 앱의 작성 중 상태를, `beforeReload`에는 복원할 화면 상태를 연결한다. 서비스 워커의 캐시 삭제는 자기 앱의 접두사에만 한정하고 사용자 데이터 저장소를 삭제하지 않는다.
