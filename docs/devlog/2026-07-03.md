Tiny Week 구현 작업 지시서를 기준으로 아이폰 가로 화면에서 7일 식단, 보이드문, 영화 일정을 한 화면에 표시하는 정적 PWA 초안을 구현했다. 기존 작업 폴더에 준비된 메뉴 이미지를 그대로 사용하고, 별도 이미지 생성 없이 앱 코드와 데이터 구조, PWA 기본 파일을 구성했다.

## Decisions

* 기존 프로젝트 파일이 지시서와 이미지뿐이었기 때문에 빌드 도구 없이 정적 PWA 구조를 선택했다. 작은 개인용 현황판이라는 목적에 비해 프레임워크를 추가하면 배포와 유지 비용이 커진다고 판단했다.
* 날짜별 식단과 영화 데이터는 지시서의 권장 구조처럼 로컬 날짜 키 `YYYY-MM-DD`를 기준으로 저장했다. UTC 변환으로 날짜가 밀리는 문제를 피하기 위해 `Date`를 로컬 연월일 생성 방식으로 다루었다.
* 주 기본 식단은 날짜 데이터 존재 여부가 아니라 별도의 주 초기화 맵으로 관리했다. 사용자가 이후 변경한 값이 앱 재실행 시 기본값으로 되돌아가지 않도록 하기 위한 결정이다.
* 보이드문 JSON은 연도별 파일을 읽되, 브라우저가 로컬 파일 직접 열기 환경에서 JSON fetch를 막을 수 있어 동일한 샘플 데이터를 앱 내부 fallback으로도 보관했다.
* 보이드문 연결 표시는 정확한 시간 길이 비례 타임라인 대신 한 줄 텍스트와 얕은 띠 배경으로 처리했다. 작은 가로 화면에서 가독성을 우선하기 위한 선택이다.
* 서비스 워커는 정적 파일을 cache-first로 제공하도록 했고, CSS 수정 검증 중 이전 캐시가 남는 문제를 확인해 캐시 버전을 갱신했다.

## Current Status

Tiny Week 초기 버전의 주요 화면과 상호작용은 동작한다. 844×390 가로 화면에서 7개 열이 동일 너비로 표시되고 가로 스크롤이 발생하지 않음을 확인했다. 세로 화면에서는 `Tiny Week 가로 화면에서 사용해 주세요.` 안내가 표시된다.

식단 선택값은 새로고침 후 유지됨을 확인했다. 영화 일정은 저장 후 새로고침 유지, 다시 열어 삭제 후 새로고침 유지까지 확인했다. 다음 주 이동 시 새 주 기본 식단이 자동 입력되고, 2026년 7월 5일 밤에 시작한 보이드문 샘플 구간이 다음 주 월요일 `→ 02:40`으로 이어지는 것도 확인했다.

현재 보이드문 데이터는 구현과 표시 검증을 위한 샘플 JSON이다. 실제 운영에 필요한 전체 연도별 보이드문 데이터가 있으면 같은 구조로 교체하면 된다.

## 추가 작업 - 음식 영역 높이 안정화

### Work Summary

가로 주간 화면에서 음식 이미지 영역이 세로로 너무 길게 보이고, 음식 행 높이를 직접 줄이면 주간 프레임 전체 크기까지 함께 변하는 문제가 있었다. 이번 작업에서는 음식 행 자체를 낮은 범위로 제한하면서도 바깥 주간 프레임은 화면의 남은 높이를 안정적으로 유지하도록 레이아웃 구조를 조정했다.

### Work Completed

* `styles.css`에서 음식 행 높이를 `clamp(82px, 24dvh, 104px)` 기반으로 줄여 화면 높이에 따라 과하게 커지지 않도록 했다.
* `.app-shell`은 `100dvh` 높이를 기준으로 고정하고, `.week-frame`은 남은 공간을 채우도록 flex 값을 조정했다.
* 날짜, 음식, 보이드문 행은 명확한 높이를 갖고, 남는 세로 공간은 영화 행이 흡수하도록 grid 행 구성을 바꿨다.
* 음식 셀과 영화 셀의 자체 고정 높이는 제거하고 grid 행 높이를 따르게 했다.
* 낮은 가로 화면용 미디어쿼리에서 음식 행 높이가 160px로 오히려 커지던 값을 `clamp(72px, 25dvh, 90px)`로 낮췄다.
* 새 CSS가 PWA 캐시에 막히지 않도록 서비스 워커 캐시 버전을 `tiny-week-v5`로 올렸다.

### Decisions

음식 영역만 고정값으로 줄이면 전체 주간 프레임이 콘텐츠 높이 총합에 맞춰 다시 작아지는 구조였기 때문에, 먼저 바깥 프레임이 화면 높이 안에서 안정적으로 자리를 잡도록 바꿨다. 이후 음식 행은 `clamp()`로 제한하고 남는 공간은 영화 행에 배분하는 방식이 가장 단순하고 조정하기 쉽다고 판단했다.

### Current Status

음식 영역은 기존보다 낮아졌고, 음식 행 높이를 조정해도 주간 프레임 전체가 함께 줄거나 늘어나는 느낌이 줄어든 상태다. 정적 서버 응답에서 새 CSS 값이 포함되는 것을 확인했다.

### Next Steps

* 실제 iPhone 가로 PWA 화면에서 음식 이미지와 영화 행의 체감 비율을 확인한다.

## 추가 작업 - 날짜 표기와 보이드문 배경 정리

### Work Summary

주간 화면의 날짜 표기를 한국어 요일과 점 표기에서 영어 요일과 슬래시 날짜 형식으로 바꿨다. 또한 보이드문 시간 표시에서 배경 레이어가 두 겹으로 겹쳐 테두리처럼 보이는 문제를 정리했다. inspect mode에서 `--void` 배경을 끄면 원하는 상태가 된다는 확인을 기준으로 수정 방향을 잡았다.

### Work Completed

* 요일 배열을 영어 약어 `Sun`부터 `Sat`까지로 변경했다.
* 날짜 셀을 `Fri 7/3` 형식으로 표시하도록 수정했다.
* 주간 범위는 `7/3-7/9`처럼 슬래시 기반 형식으로 맞췄다.
* 모달 제목과 접근성 라벨에 쓰이는 날짜 함수도 영어 요일과 슬래시 형식으로 통일했다.
* 보이드문 활성 셀의 `--void` 기반 linear-gradient 배경을 제거하고, 실제 강조 막대인 `::before` 레이어만 남겼다.
* 사용하지 않게 된 `--void` CSS 변수도 제거했다.
* 깨져 있던 보이드문 시간 라벨 문자열을 `14:20-18:05`, `until 02:40`, `23:10+` 형식으로 정리했다.
* 새 JS/CSS가 캐시에 막히지 않도록 서비스 워커 캐시 버전을 `tiny-week-v6`으로 올렸다.

### Decisions

날짜 표기는 좁은 가로 화면에서 길어지지 않도록 `Fri 7/3`을 선택했다. 보이드문 표시는 약한 배경 레이어와 강조 막대가 동시에 칠해져 겹쳐 보였기 때문에, 사용자가 확인한 것처럼 약한 배경 레이어를 제거하고 단일 강조 막대만 유지하는 쪽이 가장 안정적이라고 판단했다.

### Current Status

JS 문법 검사를 통과했다. 보이드문 배경 중복 레이어는 제거되었고, 날짜 표기는 메인 셀과 보조 날짜 함수까지 영어 형식으로 통일된 상태다. 로컬 정적 서버에서 HTML, JS, CSS 응답도 확인했다.

### Next Steps
