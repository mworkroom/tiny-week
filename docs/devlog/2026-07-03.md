## Decisions

* 기존 프로젝트 파일이 지시서와 이미지뿐이었기 때문에 빌드 도구 없이 정적 PWA 구조를 선택했다. 작은 개인용 현황판이라는 목적에 비해 프레임워크를 추가하면 배포와 유지 비용이 커진다고 판단했다.
* 날짜별 식단과 영화 데이터는 지시서의 권장 구조처럼 로컬 날짜 키 `YYYY-MM-DD`를 기준으로 저장했다. UTC 변환으로 날짜가 밀리는 문제를 피하기 위해 `Date`를 로컬 연월일 생성 방식으로 다루었다.
* 주 기본 식단은 날짜 데이터 존재 여부가 아니라 별도의 주 초기화 맵으로 관리했다. 사용자가 이후 변경한 값이 앱 재실행 시 기본값으로 되돌아가지 않도록 하기 위한 결정이다.
* 보이드문 JSON은 연도별 파일을 읽되, 브라우저가 로컬 파일 직접 열기 환경에서 JSON fetch를 막을 수 있어 동일한 샘플 데이터를 앱 내부 fallback으로도 보관했다.
* 보이드문 연결 표시는 정확한 시간 길이 비례 타임라인 대신 한 줄 텍스트와 얕은 띠 배경으로 처리했다. 작은 가로 화면에서 가독성을 우선하기 위한 선택이다.
* 서비스 워커는 정적 파일을 cache-first로 제공하도록 했고, CSS 수정 검증 중 이전 캐시가 남는 문제를 확인해 캐시 버전을 갱신했다.

## Current Status

Tiny Week 초기 버전의 주요 화면과 상호작용은 동작한다. 844×390 가로 화면에서 7개 열이 동일 너비로 표시되고 가로 스크롤이 발생하지 않음을 확인했다. 세로 화면에서는 `Tiny Week 가로 화면에서 사용해 주세요.` 안내가 표시된다.

식단 선택값은 새로고침 후 유지됨을 확인했다. 영화 일정은 저장 후 새로고침 유지, 다시 열어 삭제 후 새로고침 유지까지 확인했다. 다음 주 이동 시 새 주 기본 식단이 자동 입력되고, 2026년 7월 5일 밤에 시작한 보이드문 샘플 구간이 다음 주 월요일 `→ 02:40`으로 이어지는 것도 확인했다.

현재 보이드문 데이터는 구현과 표시 검증을 위한 샘플 JSON이다. 실제 운영에 필요한 전체 연도별 보이드문 데이터가 있으면 같은 구조로 교체하면 된다.
